## 事の経緯

LazyVimを使ってPythonの開発をしようとしたとき、変なことに気付いた。
一番最初にimport文を書いているときに、Ruffでunusedの警告が出るのはまあ正常なのだが、一緒にPyrightの警告も出るのだ。

しかもunusedだけでなく、could not be resolvedとか言ってuvでインストールしているはずのパッケージが見つからないと言われるのだ。

だめだった。

setupの方は、診断を無効にするために、クライアント側のcapabilityをfalseにしているのだが、これも効いていないようだった。

何か上流の設定で、Pyrightの診断が有効になっているのかもしれないと思い、LazyVimのドキュメントを見たり、以下の記事を参照したりしてみた。

@[card](https://zenn.dev/technicarium/articles/d5585d611be26d)

そこで目に付いたのがこれである[^1]。

```lua:options.lua
vim.g.lazyvim_python_lsp = "pyright"
vim.g.lazyvim_python_ruff = "ruff"
```

これが設定されてるのが原因なのでは？と思い、コメントアウトしたり、"pyright"を"ruff"に変更してみたりしたが、どれも効果がなかった。

設定を書いたはずなのに Pyright が黙らない。
そこで :LspInfo を叩いてみると、衝撃の事実が。

Settings セクションの typeCheckingMode が off になっておらず、デフォルトのまま動いていたのだ。
設定がマージされていない……？

ここでちょいとインストール時のことを思い出してみると、Mason v2でPyrightとRuffをインストールしていたなと思い出した。
これ、Masonが罠を仕掛けているのでは？と思い、Masonのドキュメントを見てみると、Masonはインストールしたサーバーを自動的に起動してくれるらしい。

ここで、LazyVim のプラグイン読み込み順序と、`config = true` による先行セットアップの罠に気づいた。

どうやらmason-lspconfig などで `config = true`を指定すると、LazyVimがエクストラなどの設定を考慮したセットアップ手順をスキップして、mason-lspconfigのデフォルト設定で即座にサーバーを立ち上げてしまうようだ。

というわけで、いつ書いたか分からない `config = true` を削除しつつ、setup関数でPyrightのセットアップを握り潰してみることにした。

## 最終的な設定

```lua:lsp.lua
return {
  -- lsp icons like vscode
  {
    "onsails/lspkind.nvim",
    -- nvim-cmp.lua
    event = "InsertEnter",
  },
  -- mason.nvim and mason-lspconfig.nvim
  {
    "mason-org/mason.nvim",
    version = "*",
    build = ":MasonUpdate",
    cmd = { "Mason", "MasonInstall", "MasonUninstall", "MasonUninstallAll", "MasonLog", "MasonUpdate" },
    opts = {
      registries = {
        "github:mason-org/mason-registry",
      },
    },
    -- Removed config = true to let LazyVim handle it
  },
  -- mason-lspconfig configuration
  {
    "mason-org/mason-lspconfig.nvim",
    event = { "BufReadPre", "BufNewFile" },
    dependencies = {
      { "mason-org/mason.nvim" },
      { "neovim/nvim-lspconfig" },
    },
    opts = {
      ensure_installed = {
        "jdtls",
      },
    },
    -- Removed config = true to let LazyVim handle it
  },
  -- lsp server configurations
  {
    "neovim/nvim-lspconfig",
    opts = {
      servers = {
        -- pyright: Configure but we will handle its setup manually to silence it
        pyright = {
          settings = {
            python = {
              analysis = {
                typeCheckingMode = "off",
                diagnosticMode = "openFilesOnly",
              },
            },
          },
        },
        -- ruff: Primary diagnostics
        ruff = {},
        -- jdtls: Java settings
        jdtls = {
          vmargs = {
            "-Dfile.encoding=UTF-8",
          },
          settings = {
            java = {
              signatureHelp = { enabled = true },
              contentProvider = { enabled = true },
              inlayHints = {
                parameterNames = {
                  enabled = "all",
                },
              },
            },
          },
        },
      },
      setup = {
        -- Take full control of pyright setup to ensure silence
        pyright = function(server, opts)
          -- Silence diagnostics
          opts.handlers = opts.handlers or {}
          opts.handlers["textDocument/publishDiagnostics"] = function() end

          -- Disable diagnostic capability
          if not opts.capabilities then
            opts.capabilities = vim.lsp.protocol.make_client_capabilities()
          end
          opts.capabilities.textDocument.publishDiagnostics = false

          -- Execute setup and return true to skip LazyVim's default setup
          require("lspconfig")[server].setup(opts)
          return true
        end,
      },
    },
  },
}
```

これでやっと余計な警告が消えて、快適にPythonの開発ができるようになった。

握り潰しというのはあまり好ましい解決策ではないかもしれないが、LazyVimの設定の複雑さを考えると、これが現実的な解決策かなと思っている。
